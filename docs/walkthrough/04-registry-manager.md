# 04. RaceRegistry и RaceManager

`RaceRegistry` загружает built-in провайдеры classloader-ом плагина и addon jar из `plugins/BNOF-Races/races/`. Каждый addon имеет свой `URLClassLoader`. При reload старые loader закрываются; некорректный provider логируется и пропускается.

`RaceManager` хранит `UUID -> raceId`, проверяет лимит мест и согласует диск с памятью. Изменение считается успешным только после успешной записи YAML; при ошибке карта откатывается, а команда сообщает сбой.

При смене расы manager:

1. удаляет предметы старой расы;
2. снимает только состояние, которым владела старая раса;
3. ставит transient attribute modifiers, не меняя base values;
4. применяет безусловные пассивы и подходящие по текущему условию conditional-пассивы, затем `onApply`;
5. выдаёт недостающие предметы.

Перед `/race reload` сохраняются старые объекты активных рас. После загрузки нового registry каждый онлайн-игрок очищается по старому provider и применяется по новому, поэтому удалённые способности и предметы не остаются висеть.

`refreshPassiveEffects` не переустанавливает атрибуты, здоровье или предметы. Он вызывается после смены измерения, пробуждения и каждые пять минут; именно поэтому снятый молоком эффект сохраняет отсутствие до следующего refresh.
