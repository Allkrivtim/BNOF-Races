# 06. Хранение и config

`RaceStorage` возвращает признак успеха записи. `YamlRaceStorage` сохраняет snapshot в `races.yml.tmp`, затем использует atomic move; если файловая система его не поддерживает, выполняется обычный replace. Ошибка создания каталога или записи не маскируется.

Формат:

```yaml
players:
  <uuid>: seraphim
```

Runtime-записи сериализуются в отдельном daemon storage-потоке. Пока одна мутация сохраняется, следующая возвращает `BUSY`; команда сообщает успех только после durable save. При выключении незавершённая запись ожидается с таймаутом, затем worker закрывается. Тест проверяет round-trip во вложенный новый каталог.

`PluginConfig` валидирует минимальные интервалы и перечитывается `/race reload`. Текущие ключи перечислены в корневом README; `height-datapack-enabled` управляет только автоматической установкой и не удаляет уже установленный пакет.
